# 자기 개선·지식 자산화 — 다음 고려사항 (2차 제약)

> 2026-06-14. 이미 구현된 것(P1-1~P3-10, self-improve L1~L3, cron)을 전제로,
> 시스템이 성숙하며 드러나는 **구속 제약·2차 문제**를 정리. "기능 추가"가 아니라
> "지금 무엇이 개선을 가로막는가".

## 0. 가장 중요한 제약: 평가 기질(substrate)이 없으면 loop는 헛돈다

이번 세션에서 모든 측정이 **합성 데이터에서 P@1=1.0으로 포화**됨을 반복 확인했다
(임베딩 비교·L2 게이트·리트리벌 A/B 전부). 의미:

- **자기 개선 loop는 현재 "개선할 신호"가 없다.** 측정·진단·제안 배관(L1~L3)은
  완성됐지만, 흐를 물(실제 정답/결과 신호)이 없다.
- L2 무회귀 게이트도 포화된 벤치마크 위에선 변화를 구분 못 한다.

→ **최우선은 기능이 아니라 "실제 평가 기질" 확보.** 세 경로:
1. **실데이터 hold-out** — 실 Jira 이슈의 동결 평가셋(사람 라벨).
2. **P1-3 eval_pairs 축적** — 사용자의 "실제 근본원인" 라벨이 곧 ground truth.
3. **현장 결과(outcome)** — 아래 1번.

이게 없으면 나머지 모든 고려사항은 측정 불가다.

## 1. 결과·효능 추적 (close the field loop) — 누락된 궁극의 ground truth

현재 P1-3은 "추천이 **도움됐나**(클릭)"만 잡는다. 잡지 못하는 것:
- 추천한 해결책이 **현장에 적용되어 실제로 문제를 해결했는가?**
- 적용 후 **같은 고장이 재발했는가?**(해결책 무효 신호)

→ Jira 상태 전이(해결→재오픈)·후속 댓글을 추적해 **해결책 효능 점수**를 산출.
이것이 자산을 **자기 검증**하게 만든다(추천→적용→결과→가중치 환류). P2-5 신선도가
"시간"이라면, 이건 "효능"에 의한 폐기/승격.

## 2. 지식 일관성·모순 관리 (consistency) — 규모가 키우는 문제

큐레이션 지식·Known-Issue 기사·부정지식이 쌓이면 **서로 모순**한다:
- 같은 고장모드에 다른 근본원인을 주장하는 두 기사.
- 한때 검증된 해결책이 후속 사례로 반증됨(→ 부정지식과 충돌).

현재 모순 탐지·중재 장치가 없다. → **모순 탐지(임베딩 근접 + 근본원인 상이),
"disputed" 상태, 최신·효능 기반 중재.** 자산이 커질수록 신뢰도를 좌우.

## 3. 큐레이션 경제학 / 능동 학습 (where human effort pays most)

전 자산이 사람의 승인·라벨링에 의존한다(병목). 그러나 **어떤 티켓을 큐레이션하면
KB 가치가 가장 오르는지** 모델이 없다.
→ **능동 학습식 우선순위**: 지식공백(P3-8) 빈출 + 저커버리지 + 고질의 영역의 사례를
"이걸 먼저 문서화하라"고 제안(L3 확장). 사람 노력 대비 커버리지 이득 최대화.

## 4. loop 자체의 거버넌스·안전 (governing the governor)

L2가 파라미터를 자동 적용할 수 있게 되면(현재는 사람 apply) 필요한 것:
- **킬스위치·롤백**: 적용된 override 즉시 되돌리기(reset-param은 있음) + **이상 시 자동 롤백**.
- **드리프트 경보 임계**: drift는 계산하나 알람 없음 → 지표 급락 시 통지.
- **카나리/온라인 가드레일**: 오프라인 게이트 통과해도 라이브 회귀 가능 → 일부 트래픽
  카나리 + 실시간 모니터.
- **측정자 측정(meta-eval)**: loop가 실제로 결과를 개선했는가? loop 도입 전후 ROI 비교.

## 5. 접근 통제·보존·규정 (compliance) — 조직 자산의 전제

KB에 **고객사·FW버전 등 민감 정보**가 들어있다. 조직 자산이 되려면:
- **KB 수준 접근 통제**(누가 어느 고객 사례를 조회 가능한가) — 현재 서비스계정 최소권한뿐.
- **보존 정책**(오래된 고객 데이터 만료/익명화), **PII 처리**.
- **감사 로그**: 지식 변경(승격·폐기·L2 적용·L3 실행)의 통합 변경 이력(누가·언제·왜).

## 6. 통계적 유효성·콜드스타트

피드백·결과 신호는 **표본이 적을 때 노이즈**다.
→ **최소 표본 게이팅**(N건 미만이면 자동 판단 보류), 신뢰구간, **impression 로깅**
(현재 gap만 로깅 — CTR 분모인 "노출"이 없어 유용성 비율이 편향).

## 우선순위 (정직)
1. **#0 실제 평가 기질 + #1 결과 추적** — 이것 없이는 자기 개선이 작동 불가. 최우선.
2. **#2 모순 관리** · **#3 능동 학습 큐레이션** — 자산 규모가 커질 때 신뢰도·효율.
3. **#4 loop 거버넌스** · **#5 접근통제/보존** — 실운영·다사용자 진입 시 필수.
4. **#6 통계 유효성** — 위 전부의 기반(표본·편향 보정).

## 한 줄 결론
배관(L1~L3·스토어·게이트)은 충분히 갖췄다. **다음 투자는 "물"(실데이터·현장 결과
신호)과 "감사·거버넌스"**이지, 더 많은 배관이 아니다.
