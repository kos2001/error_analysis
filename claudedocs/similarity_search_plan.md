### 핵심 진단 — "유사도 점수"가 유사도가 아니다

1. **RRF 점수는 순위 기반**이라 신호 강도가 없다. BM25 1등이면 텍스트가 거의 안 겹쳐도
   `2.0/(60+0)=0.0333`. 그래서 정답 paraphrase(B)와 점심 메뉴(A)가 같은 점수.
2. 정상 질의의 0.341 중 **0.30(88%)이 칩/분류 boost**(+0.15×2)다. 즉 현재 점수는
   "텍스트 유사도"가 아니라 사실상 "메타데이터 일치 여부 + 1등 여부"를 표시하고 있다.
3. 따라서 (a) UI에 보여주는 유사도, (b) 게이트 임계값, (c) RCA 댓글 신뢰도 라벨 모두
   현행 RRF 점수로는 만들 수 없다 → **강도 기반 신호 도입이 모든 작업의 선행 조건**.

### P0-1. 강도 기반 유사도 신호 도입 (선행 조건)
- `Recommender.recommend()`가 RRF 융합 점수와 별도로 매치마다
  `signals: {bm25_norm, entity_overlap, embed_cos}` 를 반환하도록 확장.
  - `bm25_norm`: BM25 원점수 / (질의 self-score 또는 max) — 0~1 정규화
  - `entity_overlap`: 겹친 엔티티 수 (그래프 랭커의 원신호)
  - `embed_cos`: 다국어 MiniLM 코사인 (fastembed 0.8.0 설치 확인됨)
- 랭킹은 지금처럼 RRF로, **표시/게이트/신뢰도는 signals로** 역할 분리.

### P0-2. coverage 게이트 (P0-1 위에서)
- 무관 질의 차단: `embed_cos < τ_e AND entity_overlap == 0` → "유사 사례 없음" 경로.
- τ는 ①정상 30건 ②paraphrase 확장셋 ③무관 질의셋의 세 분포를 그려서 결정
  (현재 데이터로는 임베딩 코사인이 가장 분리력 좋을 것으로 예상 — 측정으로 확인).
- 적용 지점: `/recommend` 응답의 `coverage`, UI 경고, RCA 댓글 skip 게이트 (공유 로직).

### P1-1. paraphrase 평가셋 구축 (모든 후속 튜닝의 측정 기반)
- 템플릿 20종 × paraphrase 2~3개 = 40~60문항 (LLM 생성 + 사람 검수, `data/eval_paraphrase.json`).
- 무관 질의 네거티브 20문항 포함 (게이트 FP/FN 측정용).
- `eval_recommender.py`에 `--dataset paraphrase` 모드 추가: P@1/P@3/MRR + 게이트 정밀도/재현율.

### P1-2. hybrid_embed 기본화 + 임베딩 캐시
- P1-1 평가셋에서 hybrid vs hybrid_embed vs (embed 단독) 비교 후 승자 채택.
- KB 임베딩 `tmp_db/kb_embeddings.npz` 사전 계산(이슈 키+해시 기준 무효화),
  서버 기동 시 재계산 제거. 게이트(P0-2)가 embed_cos를 쓰므로 사실상 필수.

### P2-1. boost 재설계
- 현행: 가산 +0.15×2가 텍스트 신호(≤0.042)를 압도 → 같은 칩이기만 하면 항상 위로.
- 후보: ① boost를 0.005 수준으로 축소(동순위 tie-breaker화) ② 곱셈 부스트(×1.1)
  ③ 칩/분류를 BM25 문서 토큰으로만 반영하고 boost 제거. P1-1 평가셋으로 A/B.

### P2-2. 한국어 토크나이저
- 조사로 BM25 원점수 66% 하락(순위는 유지되나 bm25_norm 게이트 신호가 흔들림).
- 후보: kiwipiepy 형태소 vs 음절 bi-gram 보조 인덱스. P1-1 평가셋으로 효과 측정 후 결정.
  (임베딩 게이트가 주 신호가 되면 우선순위 하향 가능)

### P3. 운영 연결
- UI "유사도 N%" 표기를 embed_cos 기반으로 교체 (현재 RRF 값은 오해 유발).
- RCA 댓글 신뢰도 라벨(높음/중간)을 signals 기반으로 산출.
