# 숫자 정확도 — 검증 기록 (2026-06)

LSI 분석에서 숫자(FW 버전·임계값·등급·단위·칩코드)는 핵심 식별자다. 검색이 숫자를
제대로 다루는지 측정하고 개선한 기록.

## 측정 도구: 숫자-only probe
각 해결 이슈의 요약+증상에서 **구별력 있는 숫자류 토큰만** 뽑아 질의로 쓰고, top-1이
같은 템플릿인지 본다(`Recommender.rank`). 숫자 식별력을 격리 측정하는 스트레스 테스트.

## 채택: 숫자-인지 토크나이저 (커밋 125dc33)
기존 `[A-Za-z0-9]+`는 `°%.-`에서 쪼개져 숫자가 파편화됐다:
`85°C→['85','c에서']`, `HS-G4→['hs','g4']`, `GDC7.4.2.684→['gdc7','4','2','684에서']`.

신규 `0x[0-9a-f]+|[a-z0-9°%]+(?:[./\-][a-z0-9°%]+)*|[가-힣]+`로 값+단위·FW버전·등급·
16진을 통째 보존하고 한글 조사를 분리.

| | 숫자-only probe P@1 | LOO | paraphrase |
|---|---|---|---|
| 기존 토크나이저 | 0.324 | 1.0 | 0.816 |
| **숫자-인지(채택)** | **0.779** | 1.0 | 0.816 |

→ **+140%, 무회귀.** 임베딩은 raw 텍스트라 무영향(BM25 경로에 한정).

## 기각: 희소 숫자 IDF 부스트(num_boost)
0.779를 더 올리려 "공유한 희소 숫자 토큰에 IDF 가중 가산"을 시험했으나 **채택하지 않음**:

| num_boost | hybrid_embed 숫자 probe | LOO | paraphrase |
|---|---|---|---|
| 0 (현행) | 0.574 | **1.0** | 0.898 |
| 0.005~0.1 | 0.64~0.684 | **0.985~0.993 ↓** | 0.898 (불변) |
| bm25/hybrid (any) | 0.779 (변화 없음) | 1.0 | 0.816 |

- bm25/hybrid: 무효(BM25 점수가 이미 숫자 반영, 작은 가산은 순위 불변).
- hybrid_embed: 효과 있으나 **반드시 LOO 회귀**(RRF 스케일에서 가산이 상대적으로 큼).
- **현실 지표(paraphrase)는 모든 값에서 불변** → 인공 probe를 위해 LOO를 깎는 트레이드오프.
- ∴ 회귀를 감수하며 채택하지 않음.

## 0.779의 잔여 한계는 본질적
miss 30건을 직접 검토: 대부분 **숫자 질의가 칩코드뿐**인 경우.
- `isocell-hp9` → 한 칩에 banding·ghosting 등 다수 고장모드 → 숫자만으론 식별 불가
- `se-secure7` → 5개 템플릿 공유

칩코드 하나로는 고장모드를 가를 수 없는 **고유 모호성**. `7500mbps vs 8533mbps`처럼
숫자로 진짜 갈리는 건 소수이며, 그건 production 전체 질의(증상 텍스트 포함)에서 해소된다.

## 결론 / 향후
- 숫자-인지 토크나이저가 검증된 깨끗한 개선(채택·배포 완료).
- 추가 향상은 **사내 게이트웨이 reranker(cross-encoder)** — 숫자를 어휘적으로 정확 비교 —
  로 production 경로에서 측정·검토 권장(게이트웨이 연결 필요). num_boost류 가산은 비권장.
